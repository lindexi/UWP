# CBus 当前需求约束

## 1. 项目目标

CBus 当前的目标是为本机进程间通信提供统一的调用入口，并同时支持 HTTP 与命名管道两种连接方式。

代码库需要保持两个清晰边界：

- `CBus`：面向客户端调用与终结点发现。
- `CBus.Host`：面向宿主运行、服务注册与消息分发。

## 2. 客户端类库要求

`CBus` 项目必须提供：

- 统一的请求与响应模型。
- HTTP 客户端连接能力。
- 命名管道客户端连接能力。
- 终结点发现能力。
- Pipe 协议的消息序列化与反序列化能力。

`CBus` 项目不承载：

- 服务注册表。
- 请求分发器。
- 宿主监听循环。
- 地址发布流程。

## 3. 宿主项目要求

`CBus.Host` 项目必须提供：

- 服务注册。
- 基于路由的请求分发。
- 真实 HTTP 监听。
- 真实命名管道监听。
- HTTP 端口发布。
- 命名管道地址发布。
- 可独立运行的进程入口。

## 4. 协议约束

### 4.1 路由

- 请求路径必须以 `/` 开始。
- 路径至少包含一个非空段。
- 路径第一段作为服务根段。
- 同一根段不能被多个服务重复注册。

### 4.2 HTTP

- 宿主必须根据收到的 HTTP 方法、路径、头和正文构造 `CBusRequest`。
- 客户端默认 HTTP 传输必须发送真实 HTTP 请求。

### 4.3 Named Pipe

- Pipe 链路必须通过真实命名管道建立连接。
- Pipe 消息必须使用确定的消息边界，避免流式读取歧义。
- Pipe 请求与响应内容必须通过 `CBusMessageSerializer` 编解码。

## 5. 发现约束

- HTTP 端口通过注册表发布。
- 命名管道地址通过文件系统发布。
- 客户端发现时必须同时读取这两部分信息。
- 任一关键信息缺失或格式错误时，必须返回明确失败。

## 6. 测试要求

- 客户端测试必须覆盖连接器、发现与消息序列化。
- 宿主测试必须覆盖注册、分发、地址发布以及真实 HTTP/Pipe 监听链路。
- 注册表与文件系统测试优先使用替身实现。
- 监听链路测试允许使用真实 loopback HTTP 与真实命名管道。
