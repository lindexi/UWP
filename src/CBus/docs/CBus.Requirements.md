# CBus 需求分析

## 1. 重构目标

CBus 需要拆分为两个核心项目，而不是将所有能力堆叠在一个类库中：

- 一个给客户端与服务安装方使用的 NuGet 包库。
- 一个可独立运行的宿主项目。

## 2. NuGet 包库需求

NuGet 包库负责提供客户端侧与安装侧能力，包含：

- 统一的请求与响应消息模型。
- HTTP 连接到 CBus 的能力。
- Pipe 连接到 CBus 的能力。
- 从注册表和文件系统发现 CBus 的能力。
- 统一的消息序列化与反序列化能力。

不应包含：

- 服务注册表。
- 请求分发器。
- 宿主监听逻辑。
- 地址发布逻辑。

## 3. 宿主项目需求

宿主项目负责提供运行期能力，包含：

- 服务注册。
- 基于路由的请求分发。
- HTTP 监听入口。
- Pipe 监听入口。
- 将 HTTP 端口写入注册表。
- 将 Pipe 监听地址写入文件系统。
- 提供可独立运行的进程入口。

## 4. 路由约束

- 请求路径必须以 `/` 开始。
- 路径第一节为全局唯一服务根段。
- 同一根段不能被多个服务重复注册。

## 5. 发现机制约束

- HTTP 端口通过注册表发布。
- Pipe 地址通过文件系统发布。
- 客户端发现时需要同时读取两部分信息。
- 任一关键信息缺失时，应给出明确失败结果。

## 6. 测试要求

- 客户端库需要测试连接器和发现能力。
- 宿主项目需要测试注册、分发、发布与监听适配能力。
- 测试不依赖真实网络、真实注册表和真实磁盘。

本轮交付必须包含：

- 需求分析文档。

- 用法文档。
- 经验文档。
